## Cómo se aplicó cada enfoque

- **Zero Trust:** ningún componente confía en otro por estar en la misma red; cada operación exige autenticación del sujeto y del servicio, y una decisión de autorización actual (R04, R06–R10, R15).
- **Secure by Design:** los controles forman parte de la arquitectura desde el inicio: separación de servicios y almacenamientos, firma asimétrica, deny by default, validación estricta de archivos (R01, R05, R11–R14, R19).
- **Shift Left Security:** las pruebas de seguridad se escribieron **antes** de la implementación en los componentes críticos (tareas marcadas TDD: login, guards, endpoint interno, cliente de autorización, validación de archivos, detector) y se ejecutan en cada commit (R02, R18).

**Verificación de esta matriz (tarea D3, 2026-11-04):** cada evidencia citada se comprobó contra el repositorio y las suites se ejecutaron en esta revisión: STEGO `pytest -q` → 146 passed; AUTH `npm run test` → 47/47; AUTH `npm run test:e2e` → 79/79; colección Postman 73/73 ([`newman.txt`](evidencias/newman.txt)). Los controles sin test automatizado se indican como tales en la columna Evidencia.
